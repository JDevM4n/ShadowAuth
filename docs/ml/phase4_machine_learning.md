# ShadowAuth - Phase 4 Machine Learning

## 1. Objective

The Machine Learning phase of ShadowAuth implements the mechanisms required
to train, evaluate and validate behavioral detection models using normalized
security sessions generated by the platform.

The objective is to identify suspicious behavior related to attacks while
maintaining a controlled false-positive rate.

---

## 2. Dataset

ShadowAuth generates session-level feature vectors from normalized security
events.

The master dataset may contain the following labels:

- attack
- benign
- unlabeled

Only sessions with confirmed ground-truth labels (`attack` or `benign`) are
used for supervised learning.

Unlabeled sessions remain available for unsupervised anomaly detection.

### Current feature categories

The dataset includes behavioral characteristics such as:

- session duration
- command count
- unique command count
- login attempts
- successful login
- downloads
- process activity
- shell spawning
- sensitive file access
- event severity
- session hour
- weekend activity

Network identifiers such as IP addresses and raw ports are excluded from the
supervised feature set to reduce the risk of learning environment-specific
artifacts.

---

## 3. Selected Models

Three Machine Learning approaches were selected.

### Random Forest

Random Forest is used as the principal supervised baseline.

It was selected because it:

- works effectively with tabular data
- models nonlinear relationships
- supports feature importance
- is relatively robust
- provides a strong baseline for comparison

### XGBoost

XGBoost is used as a supervised challenger model.

It provides:

- gradient boosting
- nonlinear decision boundaries
- feature importance
- configurable hyperparameters
- strong performance on structured tabular datasets

### Isolation Forest

Isolation Forest is used as a complementary unsupervised anomaly detector.

It can operate on unlabeled sessions and produces an anomaly score.

An anomalous session is not automatically considered malicious. The anomaly
score is intended to become an additional signal in the ShadowAuth correlation
pipeline.

---

## 4. Dataset Splitting

The supervised dataset is split using stratification to preserve the
distribution of `attack` and `benign` classes.

Metadata fields are removed before training.

The current experimental dataset is still small, so results obtained during
development are considered technical pipeline validation and not final model
performance.

---

## 5. Model Evaluation

The supervised models are evaluated using:

- Accuracy
- Precision
- Recall
- F1-score
- Confusion Matrix
- ROC-AUC

For ShadowAuth, special attention is given to recall for the `attack` class.

A false negative represents malicious activity that was not detected by the
model.

Precision is also monitored because excessive false positives can reduce the
operational usefulness of the detection platform.

---

## 6. Preliminary Technical Experiment

A preliminary comparison between Random Forest and XGBoost was executed using
the same train/test split.

The available labeled dataset contained only eight sessions:

- 4 attack
- 4 benign

The training split contained six sessions and the test split contained two
sessions.

### Random Forest

The preliminary test produced:

- Accuracy: 0.50
- Precision: 0.00
- Recall: 0.00
- F1-score: 0.00
- ROC-AUC: 1.00

The model classified both test sessions as benign.

The ROC-AUC result indicates that probability ranking and final classification
threshold behavior must be analyzed separately.

### XGBoost

The preliminary test produced:

- Accuracy: 0.50
- Precision: 0.50
- Recall: 1.00
- F1-score: approximately 0.67
- ROC-AUC: 0.50

The model detected the attack session but also classified the benign session as
an attack.

These values must not be interpreted as final model performance because the
test set contained only two sessions.

---

## 7. Hyperparameter Tuning

ShadowAuth includes a hyperparameter tuning pipeline based on GridSearchCV and
stratified cross-validation.

The tuning implementation currently supports:

### Random Forest

- n_estimators
- max_depth
- min_samples_split

### XGBoost

- n_estimators
- max_depth
- learning_rate

Recall is currently used as the primary optimization metric.

Definitive hyperparameter selection will be performed after additional
ground-truth sessions are available.

---

## 8. Model Validation

Repeated stratified cross-validation is implemented to measure model stability.

The validation process calculates the mean and standard deviation of:

- Accuracy
- Precision
- Recall
- F1-score
- ROC-AUC

A minimum number of labeled sessions is required before validation is allowed.

This prevents extremely small datasets from being treated as statistically
meaningful model validation.

---

## 9. Current Limitations

The primary limitation is the current quantity of labeled ground-truth
sessions.

Although the honeypot continues to collect additional activity, most captured
sessions are initially unlabeled.

The quantity of captured sessions should therefore not be confused with the
quantity of sessions available for supervised training.

Additional attack and benign sessions must be reviewed or generated using
controlled procedures before definitive model evaluation.

---

## 10. Current Status

The Machine Learning pipeline currently provides:

- dataset generation
- dataset validation
- supervised dataset splitting
- Random Forest training
- XGBoost training
- Isolation Forest anomaly detection
- prediction probabilities
- feature importance
- evaluation metrics
- hyperparameter tuning infrastructure
- repeated stratified cross-validation
- automated tests

Definitive model comparison and tuning will be repeated once a larger
ground-truth dataset is available.
